# RSS → Telegram бот

Простий бот на Node.js без зайвих залежностей: кожні 10 хвилин перевіряє RSS-стрічку
і публікує нові статті в Telegram-канал. Парсинг RSS зроблено вручну (regex),
без сторонніх бібліотек типу `rss-parser` — щоб усе було просто й прозоро.

## Що потрібно

- Node.js версії 18 або новішої (для вбудованого `fetch`). Перевір: `node -v`
- Telegram-бот, створений через [@BotFather](https://t.me/BotFather) — отримаєш токен
- Telegram-канал, де бот доданий як **адміністратор**

## Встановлення

Залежностей немає — нічого встановлювати через npm не потрібно.

```bash
cd rss-bot
```

## Налаштування

Відкрий `config.js` і заповни:

```js
module.exports = {
  TELEGRAM_BOT_TOKEN: "1234567890:AAExample-Token",
  TELEGRAM_CHANNEL_ID: "@my_channel", // або "-1001234567890"
  RSS_URL: "https://example.com/rss.xml",
};
```

### Як отримати ID каналу

- Якщо канал публічний — просто вкажи `@username_каналу`.
- Якщо приватний — додай бота [@userinfobot](https://t.me/userinfobot) в канал
  або перешли повідомлення з каналу боту [@getidsbot](https://t.me/getidsbot), щоб дізнатись числовий ID (виду `-100...`).

**Важливо:** бот має бути доданий у канал як адміністратор з правом публікації повідомлень.

## Запуск

```bash
node bot.js
```

Бот одразу зробить першу перевірку (запам'ятає поточну останню статтю, без публікації —
щоб не заспамити канал старими постами), а далі перевірятиме кожні 10 хвилин.

## Як тримати бота запущеним постійно

Для локального сервера/VPS зручно використати `pm2`:

```bash
npm install -g pm2
pm2 start bot.js --name rss-bot
pm2 save
```

## Структура файлів

- `bot.js` — основна логіка (перевірка RSS + надсилання в Telegram)
- `config.js` — твої налаштування (токен, канал, посилання на RSS)
- `last-seen.json` — створюється автоматично, зберігає посилання останньої опублікованої статті

## Обмеження цієї простої версії

- Парсер підтримує стандартні RSS 2.0 (`<item>`) і Atom (`<entry>`) фіди.
  Якщо фід має нестандартну структуру — можливо, доведеться трохи підправити regex у `parseRss()`.
- Немає обробки помилок мережі з повторними спробами — при збої просто пропускається одна перевірка,
  наступна відбудеться через 10 хв.
- Стан зберігається у простому JSON-файлі, без бази даних — цього достатньо для одного RSS-фіда.
